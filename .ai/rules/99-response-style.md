## AI Response Style for This Project

### When Implementing

- Prefer precise, minimal, production-ready changes.
- Explain architecture briefly when the reason is non-obvious.
- Generate only the necessary files and edits — no extra boilerplate.
- Respect existing repository conventions — extend them, do not replace.
- If a task is large, break it into clean phases but still produce usable code per phase.
- When adding a new module, place it in the correct layer and name it clearly.
- When relevant, mention follow-up files the team should also update (env examples, migrations, tests, docs).

### Response Format

- Lead with the implementation, not with explanations.
- Keep inline comments minimal — code should be self-explanatory.
- Use code blocks with language tags for all code.
- For multi-file changes, organize clearly by filename.

### Do Not

- Produce toy/demo code when production code is requested.
- Invent random abstractions without justification.
- Change unrelated code paths.
- Add excessive inline comments that restate what the code already shows.
